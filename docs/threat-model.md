# Threat model

What Gatehouse defends against, what stops each attack, and the test that shows it. A test named here must exist and must contain the quoted title: `apps/host/test/threat-model.test.ts` reads this file and checks every reference, so a renamed or deleted test fails the build instead of leaving a claim with nothing behind it.

## What is trusted

- **This computer, and the signed-in user.** Gatehouse runs as the user. It cannot defend against malware running as the same user.
- **The policy files**, which the user owns.
- **Claude Code's own binary**, unmodified, signed in through Anthropic's own flow.

## What is not trusted

- **Anything Claude reads or writes**: files, web pages, tool output. It can carry instructions meant to trick the model, the judge or the person.
- **Another web page open in the browser.** It can send requests to localhost.
- **The network between the browser and the Host**, other processes on the machine that are not the user, and the **Relay**, which only ever holds ciphertext.
- **The phone's request**: it is believed only after the Host has verified it.

## Known limits

- **Malware running as you** can read what Gatehouse can read and talk to the Host and the Approver. The loopback token only stops other web pages and other users.
- **The Relay can drop or delay messages**, so a phone decision may not arrive. The desktop still works.
- **Redaction is pattern based.** A secret in an unusual form can reach the audit log or the phone. The user's own list of words catches the rest.
- **The first judge call is slow** (about 25 seconds with a cold start), so judge-eligible calls wait longer while the judge is on.
- **A policy that is too loose is still too loose.** The floor and the deny list are the safety net, and the tests above show that they hold, but an allow rule you write is yours.
- **Real iPhone behaviour** (passkey, Home Screen app, push) is covered by the checks in `docs/relay-local.md`, not by an automated test.
