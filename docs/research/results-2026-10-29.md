# JCVC research results: making JCVC better than every official Claude Code surface (29 October 2026)

The Section E answer is unfavourable: Anthropic's current terms say subscription (OAuth) sign-in is "designed to support ordinary use of Claude Code and other native Anthropic applications", tell anyone building on the Agent SDK to use API keys, and say third-party developers may not offer claude.ai login "unless previously approved". No Anthropic page explicitly permits a personal Agent SDK app like JCVC to run on a Team or Enterprise SSO login, so JCVC's current authentication model is unapproved and can be blocked "without prior notice".

## TL;DR

- **Authentication is the project's biggest risk.** JCVC does not offer login to others, does not read tokens and completes sign-in through Claude Code's own flow, which removes it from the explicitly banned cases. It is still not a "native Anthropic application", and the Agent SDK overview's "unless previously approved" rule covers it. Get written approval from your company's Claude admin or Anthropic account team, or move JCVC to an API key or an organisation gateway, before you invest further.
- **The official Desktop Code tab now has most of the features on your "not built" list.** It has worktrees per session, split view, an integrated terminal, diff comments, side chats, a context card, PR monitoring and scheduled tasks. Anthropic announced the redesign on X (@claudeai) on 14 April 2026: "You can now run multiple Claude sessions side by side from one window, with a new sidebar to manage them all", and it "also adds an integrated terminal, file editing, HTML and PDF preview, and a faster diff viewer." JCVC can only beat it on oversight: programmable approvals, approval cards that show effects, a native Windows sandbox, audit, cross-session review and phone approvals that work through policy.
- **The highest-value work, in order:** fix the auth posture, close an auto-mode hole in your Approver (the `destructiveHint` caveat), show the effects of each action in approval cards, add a Windows-native sandbox, and add context, usage and compaction controls. Parity features (terminal, worktrees, session management) come after these.

## E. Risks (highest priority)

### E1. Subscription login in a third-party Agent SDK app (high risk, unresolved)

What the documents say now (all fetched 29 October 2026):

| Source | Exact wording | What it means for JCVC |
|---|---|---|

| Same page | "Developers building products or services that interact with Claude's capabilities, including those using the Agent SDK, should use API key authentication through Claude Console or a supported cloud provider." | "Should", not "must". How the terms changed:

- **January 2026:** Anthropic engineer Thariq Shihipar said Anthropic had blocked third-party tools that were "spoofing the Claude Code harness". The Register (20 Feb 2026) and WinBuzzer reported that enforcement started on 9 January 2026.
- **17-18 February 2026:** the Legal and compliance page changed. GitHub issue AndyMik90/Aperant #1871 (opened 18 Feb 2026) says the change was "observed around Feb 17-18, 2026", Rob Zolkos posted the wording on X on 18 February, and The Register confirmed it on 20 February. The text began "OAuth authentication (used with Free, Pro, and Max plans) is intended exclusively for Claude Code and Claude.ai" and went on: "Using OAuth tokens obtained through Claude Free, Pro, or Max accounts in any other product, tool, or service, including the Agent SDK, is not permitted and constitutes a violation of the Consumer Terms of Service." Shihipar then posted that "Nothing is changing about how you can use the Agent SDK and MAX subscriptions!" (reported by Autonomee).
- **19 March 2026:** OpenCode removed built-in Anthropic auth (PR #18186) after server-side 400 and 401 rejections (yage.ai, 21 Mar 2026).
- **By 7 October 2026:** the explicit Agent SDK ban had gone from the page, replaced by the current wording (Autonomee, updated 26 Oct 2026, and the fetched page).
- **Issue #42106**, "Allow OAuth/subscription tokens with Agent SDK for personal development use", was closed as not planned. The subagent found no counts for it.

Assessment:

- JCVC is not in any explicitly banned category. It does not spoof the harness, extract tokens, resell or intermediate.
- It is also not in any explicitly permitted category. The only safe harbour named on the page is the unmodified Claude Code binary, and the SDK overview requires prior approval for SDK products that offer claude.ai login.
- Your login is company SSO, which means a Team or Enterprise plan under the Commercial Terms. The "on behalf of their users" ban names only Free, Pro and Max credentials. Your employer's Claude admin is the party who can approve or forbid JCVC.
- Whether a private desktop tool counts as "building products or services" is a judgement. Anthropic has not ruled on it.

What to do:

1. **Get approval in writing.** Ask your organisation's Claude Owner, and through them the Anthropic account team, to approve JCVC as a personal SDK host on the org's SSO login. The Legal and compliance page sends questions about permitted authentication to sales. Keep the approval in the repository.
2. **Build a compliant fallback now.** Support three auth modes, chosen at start-up: (a) the plan login through Claude Code's own flow (current), (b) an API key from a Console organisation, or Bedrock, Vertex or Foundry, set by environment and never read by JCVC, (c) the Claude apps gateway, which lets developers "sign in with your corporate identity provider (IdP) instead of holding API keys" (Claude apps gateway docs).
3. **Know what you lose on an API key.** Remote Control "requires claude.ai subscription auth", and API keys are not supported (Remote Control docs). Your own relay to the iPhone does not depend on Remote Control, which is a reason to keep it.
4. **Never add token handling.** Do not add features that read, cache or forward the credentials Claude Code stores. That is the exact behaviour Anthropic enforced against in January 2026.
5. **Monthly API credits do not help you.** Since 7 October 2026, Max and Team plans include monthly API credits for the Agent SDK, used through a linked Console API key: $100 on Max 5x, $200 on Max 20x, and $20 or $100 per Team seat pooled up to $500 (Autonomee summary of the Help Centre). Free, Pro and Enterprise are not eligible. If your company is on Enterprise, there are no credits.
